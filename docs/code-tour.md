# Code tour and extraction boundaries

| Inspect | Origin and decision |
| --- | --- |
| [LocalObjectStore](../packages/ingestion/local_object_store.py), [storage protocol](../packages/ingestion/object_store.py) | Retained local write-once implementation and digest verification. Cloud backends are excluded. |
| [Financial tables](../packages/db/models.py), [baseline and triggers](../migration.sql) | Selected financial and scenario ORM classes retain their constraints. Company and document identity are reduced to the fields this walkthrough needs. The transactional showcase baseline adapts the source's immutable-row and close-once trigger pattern to these tables. Its exclusion constraint makes overlapping financial versions impossible. |
| [known_at](../temporal.py) | Existing SQLAlchemy half-open predicate, typed here for financial facts. SYSTEM_KNOWN refers to approved canonical evidence in the simulated chronology. PUBLIC_AVAILABLE needs its own source access evidence, review policy and admission checks. It is excluded. |
| [ScenarioService.run, _outputs and _financials](../scenarios.py) | Existing service and storage path with the revenue/capex branches retained. Selection adds a deterministic ID tie-breaker. Unsupported currency units raise an error instead of receiving the source normaliser's fallback multiplier. Other shocks and the private rule registry are excluded. |
| [ingest, validate, approve and promote](../evidence.py) | Standalone adaptation of the validation, analyst review, revalidation and idempotent promotion boundaries. A new fixture parser replaces the domain-specific extraction adapter. One cited line is one proposal, with one canonical fiscal fact per approved version. This adapter is narrower than the general extraction services. |
| [revenue_share_step](../transmission.py) | Generic one-step percentage arithmetic and the unknown-value and incompatible-unit stops selected from the existing transmission engine. The caller supplies a quantity. No graph traversal, admitted exposure registry or empirical coefficient is shipped. |
| [freeze](../manifest.py) | Evidence-only adaptation of the snapshot service's sorted identifiers and canonical JSON SHA-256. This contract has its own schema and digest. The target and horizon are fixture values. Forecast creation, readiness, resolution, learned models and scoring are excluded. |
| [CLI](../demo.py), [statements](../fixtures), [initialisation](../database.py) | New demonstration and packaging. Fixed identifiers and times make substantive results reproducible even when scenario run IDs differ. |
| [PostgreSQL tests](../tests/test_case.py) | Exercise the actual services in a transaction-local schema. Look for database mutation attempts, rejected units, role checks, duplicate promotion, a repeated early query and stable manifest hashes. |

The only entry point is a trusted local CLI. The analyst role check demonstrates service-level validation. There are no HTTP mutation endpoints, user authentication claims or frontend contracts. The synthetic period, issuer and review chronology are intentionally fixed. There is no background ingestion, retroactive public replay, multihop propagation, missing-assumption financing model, validated predictive strategy or private research data in this extraction.
